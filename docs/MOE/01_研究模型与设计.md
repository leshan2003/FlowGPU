# 01 研究模型与设计

## 1. 研究目标

目标不是单纯比较“GPU 快还是类脑快”，而是研究：

> 在 GPU HBM、类脑 DRAM、类脑 SRAM 三层存储体系中，如何联合决定专家分层、
> 副本数量、空间位置、GPU/类脑调度和迁移时机，以最少硬件满足 SLO。

四个决策维度：

1. **存储/执行层级**：HBM、Brain DRAM、Brain SRAM；
2. **副本**：unique coverage、额外 hot replica；
3. **空间位置**：node、chip、GPU/Brain；
4. **时间刷新**：何时重算、何时迁移、如何切换版本。

## 2. 三种执行模式

| 模式 | 权重位置 | 热专家执行 | 冷专家执行 |
|---|---|---|---|
| M1 Brain-only | 全部专家在 Brain DRAM；热集在 SRAM | Brain SRAM | Brain DRAM → SRAM |
| M2 Tier-exclusive | 热专家只在 Brain SRAM；其余只在 HBM | Brain | GPU/HBM |
| M3 Overlay + parallel | HBM 保存全部；热专家另有 SRAM 副本 | GPU 或 Brain | GPU/HBM |

关键区别：

- **M1** 不依赖 GPU expert fallback；
- **M2** 每个专家只属于一个执行层；
- **M3** 保留 HBM 全备份，并允许同一专家的不同 assignment 并行走 GPU/Brain。

M3 不是“一个 expert kernel 跨 GPU/Brain 张量并行”，并行粒度是不同 token/assignment。

## 3. 三种 dispatch 路径

| 模式 | 路径 | 含义 |
|---|---|---|
| D0 | GPU → 专家 node → GPU | GPU 直接选择专家 node |
| D1 | GPU → home node → 专家 node → home node → GPU | token/route 状态绑定 home node |
| D2 | home node → 专家 node → home node | router/activation 已在 home node |

home-node 不是芯片内部结构，而是系统级 request-affinity 与路由假设。
只有当 KV/activation/router 状态确实驻留在 home node 时，D1 的额外 hop 才合理。

## 4. 连续冷热与副本

本工作不把专家固定切成 hot/cold 0/1 集。规划器使用：

```text
demand(layer, expert)
+ node-demand / home affinity
+ coactivation / hyperedge
+ expert bytes
+ chip/node load
+ C and SRAM capacity
```

候选动作是离散的：

- 新增唯一副本；
- 给热专家增加第 2、3...份副本；
- 改变 node/chip；
- 迁移已有副本。

`R_unique` 与 `R_copy` 分开：

- `R_unique<1` 时仍允许极热专家获得额外副本；
- 不要求先覆盖所有专家才允许复制。

## 5. C、node、batch

- `C`：每颗 chip 的 expert 数上限；
- `copies`：Brain 侧总专家副本预算；
- `nodes/chips`：容量、locality 和并行度；
- `batch`：同时进入 decode 的 request 数。

C 不会直接形成串行链；它限制 packing 和 hot coverage。

当前两套 C 实验：

- `64 copies / 64 chips`；
- `32 copies / 16 chips`；
- D0 C 网格使用 `32-copy budget`，让 C=1/2/4 产生不同有效 hot coverage。

## 6. 聚类目标

聚类不是只追求 pair cut。真实目标至少包含：

```text
cross-node fanout
+ intra-node chip fanout
+ request-home → replica communication
+ D0 GPU bridge/combine
+ max/mean node and chip load
+ C/SRAM feasibility
```

当前比较：

- unique-balanced；
- pair-clustered；
- full-hyperedge。

重要区别：

```text
共激活专家放在同一 node
≠
该 node 是请求真正来源的正确 node
≠
端到端 completion 一定改善
```

聚类结论必须同时报告 node cut、remote fraction、completion、P99 和负载。

## 7. 刷新

刷新拆成四步：

1. 历史窗口更新统计；
2. 重算 placement；
3. source-aware migration；
4. 新版本完整后激活，并保护在途请求。

当前实现：

- drift 检测和 hysteresis；
- GPU→Brain、Brain→Brain 等 source-aware migration；
- migration 与 serving 共享 `FluidNetwork`；
- 旧请求保留旧版本，新请求使用新版本。

目前只完成前两层代表 flow replay，尚不能给完整模型 refresh ROI。

| 轴 | 典型取值 |

| 模型 | Mixtral、DeepSeek-V3、Qwen3、gpt-oss |

| batch | 1 / 4 / 16；另有 64 高 batch 专项 |

| copies | 最小唯一覆盖、32、64 |
| dispatch | D0 / D1 |
| placement | unique / pair / full-hyperedge |
| mode | M1 / M2 / M3 |
